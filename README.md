# 📖 Подстрочник

Приложение для Android, которое **переводит текст прямо на экране телефона**.

Запустили его, открыли YouTube или игру — приложение распознаёт надписи,
переводит их на русский и подставляет перевод на место оригинала. При этом
оригинал закрашивается цветом своего же фона, а не закрывается непрозрачной
плашкой: картинка остаётся живой, и перевод не мешает смотреть.

> Работает поверх других приложений, потому что Android разрешает рисовать
> поверх окон, если пользователь на это согласен. Ничего не взламывается и
> никуда не отправляется, кроме самой строки перевода.

---

## 📲 Как установить

1. 📁 Откройте папку `Download/API_translator` в памяти телефона.
2. 👆 Нажмите на `app-debug.apk`.
3. 🔓 Если спросит разрешение на установку из неизвестных источников —
   разрешите для того приложения, из которого открываете файл (обычно это
   «Файлы» или «Диск»).
4. ✅ После установки откройте **Подстрочник** и нажмите «Запустить перевод».
5. 🔴 Телефон спросит разрешение на «захват экрана» — это стандартный запрос
   Android на демонстрацию экрана. Нажмите «Начать захват» и сразу вернитесь
   в приложение. Его можно свернуть: перевод продолжит работать.

Ключ перевода уже вшит в файл, вводить его руками не нужно.

---

## 🔐 Какие разрешения нужны и зачем

| Разрешение | Зачем |
|---|---|
| 🖥️ Захват экрана | Без него Android не даст увидеть, что нарисовано на экране. Запрашивается один раз, при запуске. |
| 🪟 Показ поверх других приложений | Нужен, чтобы перевод рисовался поверх YouTube или игры. В настройках Android называется «Отображение поверх других приложений». |
| 🔔 Уведомления | Android требует видимое уведомление у любой службы, которая что-то делает в фоне. В нём же кнопка «Остановить». |

## 🧠 Как это работает

```
 📱 экран телефона
      │
      │  снимок кадра
      ▼
 🔍 ML Kit ──► распознанные строки и их координаты
      │
      │  только то, что держится на экране
      ▼
 🌍 DeepL ──► перевод на русский
      │
      ▼
 🖍️ оверлей: оригинал закрашен, перевод написан поверх
```

Картинка не выгружается никуда. По сети уходит **только текст**, который
нужно перевести.

## 😅 Что пошло не так

Здесь честный список настоящих ошибок. Не опечаток, а тех, из-за которых
приложение либо не запускалось, либо переводило чушь, либо падало.

### 💀 Процесс убивался нативно, мимо `try/catch`

Самое неприятное. Вместо `YUV_420_888` в `ImageReader` поставили более
логичный `RGBA_8888`, и тут выяснилось, что ML Kit такие кадры не берёт:

```
Only JPEG and YUV_420_888 are supported now
```

Вернули `YUV_420_888` — и процесс начал умирать **сигналом 6** (`SIGABRT`).
Это падение внутри нативного кода Android, мимо любого `try/catch`: у
приложения не было даже шанса записать, что случилось. Экран гас, логи
достать нечем, а диагностика на телефоне показывала только «приложение
закрылось».

Спасло возвращение к `RGBA_8888` с ручной сборкой `Bitmap` вручную — медленнее,
зато предсказуемо. Заодно появилась возможность брать цвет фона обычным
`bitmap.getPixel`.

### 🖼️ Снимок экрана впихивали в чужой размер

Размер буфера вычислялся **один раз** — в момент нажатия кнопки — и
намертво запекался в `ImageReader`. Пока телефон лежал вертикально, всё
работало. Стоило положить его на бок: Android начал впихивать альбомную
картинку в портретный буфер и добавил по краям чёрные поля.

Распознавание честно вернуло рамку — но для **уменьшенной копии** картинки.
А оверлей рисовал по этим координатам, то есть мимо настоящего экрана.
Итог: в горизонтали текст перевода наезжал на пустое место.

Теперь размер экрана спрашивается каждый кадр, и при повороте захват
пересоздаётся. Буфер совпадает с экраном один в один.

### 🫧 Приложение выдумывало текст, которого нет

Главный симптом, из-за которого всё затевалось. Причины наложились одна на
другую:

- 🔁 строки сравнивались **точно**. Распознавание дрожит: «Hello, world» то
  приходит как «Неllo, wоrld», то без запятой. Каждая описка считалась новым
  текстом;
- 📦 рамка бралась из **текущего кадра**, а он на пару пикселей ездил, и
  перевод прыгал по экрану;
- 🖌️ оверлей перерисовывался **каждый кадр**, даже когда ничего не изменилось;
- 🗑️ в перевод летело всё, где есть три буквы, — включая мусор от сжатого
  видео.

Теперь строка опознаётся по ограниченному расстоянию Левенштейна, рамка
фиксируется при первом появлении и больше не меняется, а перерисовка
происходит только при реальном изменении.

### 💸 Мусор съедал лимит DeepL

Корень проблемы выше был ещё и финансовым. Каждая дрожь распознавания —
это запрос в API. Бесплатный тариф DeepL даёт 500 000 символов в месяц, и
выдуманные строки, улетевшие на перевод, съедали его быстрее, чем
настоящий перевод. Проверка «строка видна три кадра подряд» и повторное
использование рамки решают проблему сразу.

### 🎨 Закрашивали текст серым пятном

Приложение закрашивает оригинал цветом фона вокруг букв. Цвет брался по
кольцу точек вокруг рамки, и обход начинался с `i = 0` — то есть **на
самой границе букв**. Медиана брала цвет не фона, а полупрозрачных
остатков текста, и на экране появлялось серое пятно поверх слов.

Стоило сдвинуть обход на полполосы внутрь — и заливка стала брать честный
цвет фона. Ошибку нашли три теста, которые поначалу были написаны неверно
и «подтверждали» неправильное поведение.

### 📞 Android переписал сигнатуру метода

На Android 15+ у `createVirtualDisplay` стало **восемь** параметров: после
`dpi` идёт `int flags`. Старый вызов из шести аргументов на Android 16
падал на старте.

### ⚠️ Порядок запуска службы

На Android 14+ `startForeground` для типа «захват экрана» обязан вызваться
**раньше**, чем берётся сам захват. Наоборот — Android выбросит исключение.
Это неочевидно и стоило отдельного круга диагностики.

### 🔇 С телефона нельзя прочитать логи

Собрать и запустить с Termux можно, а вот увидеть, что происходит внутри
приложения на телефоне, — нет: ни процессов, ни системного лога. Поэтому в
приложение встроена своя диагностика: счётчики на главном экране, причина
падения из `ApplicationExitInfo` и кнопка, которая копирует отчёт в буфер
обмена. Сломанный CI тоже отчитывается комментарием к коммиту — логи
Actions из Termux не читаются.

## ⚠️ Ограничения — честно

- 🔤 **Движок распознавания знает только латиницу, кириллицу и греческий.**
  Это встроенная библиотека ML Kit. Японский, корейский и китайский она не
  прочитает: нужен отдельный модуль, и он заметно тяжелее.
- 🔒 **Защищённый видеопоток не переводится.** Netflix, YouTube Premium и
  часть игр рисуют картинку «поверх всего», и снимок экрана в этом месте
  чёрный. Это ограничение Android, а не ошибка приложения.
- ⏱️ **Задержка 1–2 секунды.** Кадр сначала снимается, потом распознаётся,
  потом переводится по сети. Мгновенно не получится.
- ✂️ **Длинные надписи обрезаются по высоте.** Перевод помещается в рамку
  оригинала: шрифт уменьшается до нужного размера, а если не влезает даже
  минимальный — низ текста обрезается.
- 🔁 **Русский не переводится на русский.** Очевидный текст просто
  пропускается, чтобы не тратить лимит.
- 🧹 **Мусор от сжатого видео.** Распознавание иногда принимает текстуры и
  артефакты за буквы. Фильтр ловит большую часть, но не всё: если видно
  перевод того, чего на экране нет, — это оно.

## 🌍 Про перевод

Переводит [DeepL](https://www.deepl.com), целевой язык — русский. Нужен
интернет: строка уходит на сервер DeepL.

Бесплатный тариф даёт 500 000 символов в месяц. Приложение не показывает,
сколько осталось, но проверить легко: у DeepL есть адрес
`https://api-free.deepl.com/v2/usage`, который показывает остаток по ключу.

---

## 🔨 Как собрать самому

Сборка идёт через GitHub Actions, собирать на компьютере ничего не нужно.

1. Откройте репозиторий → **Settings** → **Secrets and variables** →
   **Actions** → **New repository secret**.
2. Имя секрета строго `DEEPL_API_KEY`, значение — ключ DeepL.
3. Запушьте любой коммит в `main`.

Через несколько минут в разделе **Actions** появится сборка, а в ней —
артефакт `app-debug` с готовым `app-debug.apk`. Скачивается кнопкой
**Download artifact** прямо в браузере.

Если секрет не задан, сборка падает сразу и с понятным сообщением, а не
где-то в середине.

> ⚠️ Ключ попадает внутрь APK. Это удобно, но небезопасно: кто получит файл,
> тот сможет вытащить ключ и переводить за ваш счёт. Для личного применения
> на своём телефоне это нормально. Если ключ утечёт — отзовите его в личном
> кабинете DeepL и создайте новый.

## 🗂 Как устроен код

```
app/src/main/java/com/dmitrylegend/apitranslator/
  MainActivity.kt      экран с одной кнопкой: спросить разрешение и запустить
  TranslateService.kt  вся работа: снимок экрана, распознавание, перевод
  OverlayView.kt       рисует перевод поверх приложений, закрашивает оригинал
  Geom.kt              математика без единой строчки Android
app/src/main/res/
  drawable/            иконка (вектор, поэтому резкая на любом экране)
  mipmap-anydpi-v26/   адаптивная иконка: Android сам нарежет под свою форму
  values/strings.xml   название приложения
app/src/test/java/com/dmitrylegend/apitranslator/
  GeomTest.kt          11 проверок математики, гоняются без телефона
.github/workflows/build.yml  сборка APK в облаке
```

`Geom.kt` специально вынесен без единой строчки Android — поэтому его
проверки (`./gradlew test`) работают на обычном компьютере, без эмулятора.
Там проверяется ровно то, что ломается тихо и незаметно: пересчёт координат
при повороте экрана, подбор размера шрифта, медиана цвета фона и сравнение
строк на похожесть.

Остальное — распознавание, сеть, отрисовка — автоматически не проверить,
это видно только на реальном устройстве.

## 📦 Релизы

Готовый файл лежит на странице **Releases** репозитория: открыть репозиторий →
**Releases** справа → скачать `app-release.apk`.

```
https://github.com/DmitryLegend/API_translator/releases
```

Там же, отдельным пунктом, лежат **исходники** — GitHub прикладывает их к
каждому релизу сам, в виде `Source code (zip)` и `Source code (tar.gz)`. Это
полный код проекта, ровно тот же, что в репозитории.

| Файл | Что это | Чем отличается |
|---|---|---|
| 🔧 `app-debug.apk` | черновой, из артефактов сборки | виден всегда, ставится поверх debug-сборки, ключ подписи нестабильный |
| 📦 `app-release.apk` | подписанный, официальный | ставится поверх прошлых релизов, один ключ навсегда |

> ⚠️ Релиз подписан **другим** ключом, чем debug-сборка. Поэтому при первой
> установке `app-release.apk` Android потребует **удалить** старую debug-версию.
> Дальше всё просто: каждая следующая версия ставится поверх предыдущей,
> данные приложения не пропадают.

### 🏷️ Выпустить новую версию

```bash
git tag v1.1.0
git push origin v1.1.0
```

Сборка соберёт подписанный APK, прогоняет тесты и выложит всё на страницу
Releases с пометкой «Latest». Дальше файл скачивается оттуда.

Ключ подписи лежит в секретах репозитория (`RELEASE_KEYSTORE_BASE64`,
`RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`) и в
сам репозиторий не попадает. Пока эти секреты на месте, все релизы подписаны
одним ключом и обновляются друг поверх друга. **Потеряете секреты — новые
версии придётся ставить только после удаления старой.**
