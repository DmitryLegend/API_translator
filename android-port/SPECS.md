# SPECS: Подстрочник — Android-версия на Python

Документ для «чистой комнаты»: здесь описано, **что** программа должна делать.
Реализующий не видел исходный Kotlin-код Android-приложения и пишет только по
этому документу.

Про метод. В настоящей чистой комнате спецификацию пишет тот, кто читал
оригинал («грязная комната»), а код пишет тот, кто его не видел. Здесь обе
роли исполняет один человек, поэтому метод — дисциплина, а не юридическая
чистота: спецификация написана первой, код — только по ней, без перечитывания
оригинала.

Цель — **APK**: приложение для Android, вся логика которого написана на
Python и собирается в APK плагином Chaquopy (CPython внутри Gradle-сборки).
Чистые функции и конвейер живут в `core.py` и тестируются на любой машине;
всё, что привязано к Android, лежит в `main.py` (Activity) и `service.py`
(сервис, оверлей) и проверяется только на телефоне.

## 1. Суть программы

Служба раз в ~0.7 секунды снимает экран, распознаёт на нём текст, переводит
найденное на русский через DeepL и рисует перевод поверх экрана — ровно там,
где стоял оригинал. Оригинал закрашивается цветом **своего же фона** (не
непрозрачной плашкой), картинка вокруг остаётся живой.

## 2. Общее устройство

- Два компонента на Python, порождённых сборкой Chaquopy:
  - `MainActivity` — единственный экран: статус, одна кнопка
    «Запустить перевод»/«Остановить», автоматическое копирование отчёта в
    буфер обмена, причина прошлого падения процесса. Весь интерфейс
    собирается кодом, без файлов разметки.
  - `TranslateService` — foreground-служба: захват экрана, распознавание,
    перевод, оверлей. Живёт в том же процессе и в том же интерпретаторе
    Python, что и Activity; состояние для экрана отдаёт через переменные
    уровня модуля.
- Весь конвейер — один рабочий поток (`threading`): пока заняты
  распознавание или сеть, следующий кадр не берётся. Оверлей трогается
  только с главного потока.
- Оверлей — окно `ImageView` поверх всего экрана: TYPE_APPLICATION_OVERLAY,
  MATCH_PARENT, флаги NOT_FOCUSABLE + NOT_TOUCHABLE + NOT_TOUCH_MODAL,
  формат TRANSLUCENT. Рисование делается в Bitmap (Canvas) на рабочем
  потоке; главный поток только подменяет bitmap через setImageBitmap.
  Собственный подкласс View не используется: у статического прокси
  Chaquopy конструктор с аргументами недоступен, а View требует
  `View(Context)`.

## 3. Константы

| Константа | Значение | Смысл |
|---|---|---|
| SCAN_MS | 700 | пауза между кадрами |
| STABLE_SCANS | 3 | сколько кадров подряд должна быть видна строка, прежде чем уйти в перевод |
| LINE_TTL_MS | 4000 | строка, которой дольше этого не видели, считается ушедшей |
| MAX_LINES | 60 | предел строк в памяти; лишние вытесняются с начала списка |
| SAME_PLACE | 0.5 | порог перекрытия рамок (IoU), ниже которого это разные места экрана |
| ALLOWED_PUNCT | `" .,!?;:'\"()-%+—…"` | знаки, допустимые в настоящем тексте |
| MAX_BLOCK_CHARS | 400 | блок длиннее — мусор, не переводим |
| MIN_BOX_PX | 26 | рамка мельче по любой стороне — иконка/цифры, не текст |
| BATCH | 40 | строк в одном запросе DeepL |
| SAMPLE_BAND_PX | 3 | ширина полосы вокруг рамки для взятия цвета фона |
| TARGET_LANG | "RU" | целевой язык перевода |
| CONNECT_TIMEOUT_MS / READ_TIMEOUT_MS | 10000 / 15000 | таймауты сети |
| DPI | 100 | плотность виртуального экрана (на картинку не влияет) |
| MIN_TEXT_PX | 7.0 | мельче этого текст нечитаем — упираемся и рисуем в обрез |
| MAX_HEIGHT_GROWTH | 1.6 | во сколько раз перевод может быть выше оригинала |
| FIT_STEPS | 10 | число делений пополам при подборе шрифта |

## 4. Запуск и разрешения

Проверки выполняются по порядку; каждое «не сработало» просто возвращает
пользователя на тот же экран, где он нажимает кнопку ещё раз.

1. Ключ DeepL вшит в сборку (`keys.py` генерирует CI из секрета
   `DEEPL_API_KEY`). Если он пустой — экран объясняет, что пересобрать нужно
   с ключом, и на этом останавливается.
2. Разрешение на уведомления (Android 13+): без него фоновая работа
   невидима, и пользователь решит, что приложение сломалось.
3. Право рисовать поверх других приложений: выдаётся только в настройках
   системы, из диалога его получить нельзя. Открывается
   `ACTION_MANAGE_OVERLAY_PERMISSION` с адресом пакета.
4. Системный диалог «разрешить показывать экран» через
   `startActivityForResult`; в `onActivityResult` при положительном ответе
   служба стартует через `startForegroundService` с intent, куда сложены
   resultCode и resultData.

## 5. Жизненный цикл службы

`onStartCommand`:

- Повторный «Старт» при работающем переводе игнорируется; intent без
  разрешения на захват (`resultData == null`) — стоп без работы.
- Любое падение запуска ловится целиком, а текст ошибки со стеком (до 1200
  символов) пишется в SharedPreferences («last», ключ «error»): падение
  убивает процесс вместе с полями, а настройки переживают перезапуск, и
  экран покажет, на чём всё встало. Перед запуском старая ошибка стирается.
- **Порядок критичен на Android 14+**: сначала `startForeground` (с типом
  `mediaProjection` на Android 29+), и только потом `getMediaProjection` —
  наоборот Android выбросит исключение.
- Регистрируется `MediaProjection.Callback`: если пользователь погасил
  захват чипом из статус-бара (Android 15+), служба останавливается, иначе
  перевод навсегда зависнет поверх чужого приложения.
- Дальше: распознаватель, оверлей, рабочий поток.

`onDestroy` (строго в этом порядке): остановить цикл → освободить
VirtualDisplay → закрыть ImageReader → `projection.stop()` (иначе система
может держать захват живым) → закрыть распознаватель → снять оверлей.

## 6. Захват экрана

- Формат кадра — RGBA_8888, а не YUV: путь через YUV роняет процесс
  нативно, сигналом 6, мимо любого `try`. RGBA переводится в Bitmap напрямую
  байтами (раздел 6.1).
- Захват создаётся под **текущий** размер и поворот экрана; проверка —
  перед каждым кадром. Сменился размер или поворот — захват пересоздаётся,
  все накопленные строки и нарисованное забываются (они лежали в чужих
  координатах). Порядок: сначала создать новый, потом закрыть старый — иначе
  мигнение неудачи оставит без картинки вовсе.
- Размер экрана — `maximumWindowMetrics.bounds` (Android 30+), раньше
  `getRealSize`. Поворот — через DisplayManager: попытка узнать его из
  фонового контекста на Android 11+ заканчивается ошибкой.
- Разница поворота «после пересоздания» почти всегда ноль; ненулевые один-два
  кадра передаются распознавателю как rotationDegrees.

### 6.1. Кадр → Bitmap

У ImageReader строка буфера бывает шире картинки (выравнивание), поэтому
копия идёт построчно: буфер целиком выгружается одним вызовом в Java-массив
байтов, превращается в `bytes`, ряды собираются вплотную (порядок байтов
RGBA совпадает с внутренним представлением Bitmap ARGB_8888, пересчёта
пикселей не требуется), и всё одним вызовом `copyPixelsFromBuffer`.
Поштучный перебор миллионов пикселей из Python недопустимо медленный.

## 7. Рабочий цикл

1. Обновить захват при необходимости.
2. Взять свежий кадр (`acquireLatestImage`; нет кадра — статус «картинка
   пока не приходит»). Кадр закрывается **обязательно**, в `finally`:
   забудешь — ImageReader упрётся в лимит картинок, и захват встанет.
3. Обработать кадр (разделы 8–12). Ошибка кадра не роняет конвейер: текст
   сбоя уходит в статус, цикл продолжается.
4. Спать остаток секунды до полных SCAN_MS.

## 8. Распознавание

Движок — ML Kit Text Recognition, вариант «latin» (латиница, кириллица,
греческий; CJK нужен отдельный модуль). Кадр отдаётся как
`InputImage.fromBitmap(bitmap, rotationDegrees)`; вызов дожидается синхронно.

Для каждого блока распознавания известны: текст, рамка и язык первого слова
первой строки. Язык, начинающийся с TARGET_LANG, в перевод не идёт — русский
на русский не переводят, лимит не тратят. (Функция-эвристика «кириллицы
больше 70 %» существует в `core.py` только для случая, когда язык неизвестен:
тесты и десктоп.)

## 9. Фильтры блоков

По порядку для каждого блока:

1. текст пустой или длиннее MAX_BLOCK_CHARS — пропустить;
2. рамка уже MIN_BOX_PX по любой стороне — пропустить;
3. язык = TARGET_LANG — пропустить (счётчик «русских» +1);
4. текст не похож на текст — пропустить (счётчик «мусора» +1).

«Похоже на текст» — намеренно грубая эвристика: букв минимум 3, и не меньше
трёх четвертей символов — буквы, цифры или знаки из ALLOWED_PUNCT.
Настоящий фильтр один — стабильность на STABLE_SCANS кадрах (раздел 10):
мусор от сжатия не держится три кадра.

## 10. Идентификация строк

Строка — это «текст, который держится на экране», с фиксированной рамкой.

- Ключ строки: текст без регистра, пробелов и знаков — только буквы и цифры.
  Так дрожь распознавания («Неllo» вместо «Hello») не порождает новую строку.
- Поиск среди накопленных — двумя проходами:
  1. тот же ключ **и** та же рамка (та же рамка — IoU ≥ SAME_PLACE);
  2. та же рамка и текст отличается не более чем на 2 правки (расстояние
     Левенштейна с полосной таблицей и ранним выходом).
  Пустой ключ никогда ничего не находит.
- Не нашли — строка создаётся, и её рамка **запоминается навсегда**: свежая
  рамка от распознавания ездит на пару пикселей, из-за этого перевод прыгал
  бы по экрану. Тот же текст в другом месте экрана — другая строка.
- Строка, попавшаяся в кадре дважды (одна и та же строка приходит и целиком,
  и по кускам), второй раз не считается: сравнение по принадлежности
  объекта, не по значению, иначе счётчик прыгает сразу на два.
- Для каждой учтённой строки: счётчик кадров +1, время последнего вида
  (SystemClock.elapsedRealtime) = сейчас.

## 11. Стабилизация, устаревание, вытеснение

- Строки, которых дольше LINE_TTL_MS не видели, забываются.
- Если строк больше MAX_LINES, с начала списка (самые старые по заведению)
  удаляются лишние.
- В перевод уходит строка, у которой счётчик кадров **ровно** STABLE_SCANS и
  перевода ещё нет. Ровно, не «не меньше».

Известная особенность, сохраняется как есть: если запрос DeepL для строки
не удался, строка больше **не** отправляется, пока не исчезнет с экрана и
не появится заново (счётчик уже прошёл значение STABLE_SCANS). Это
поведение оригинала; менять его — значит делать не порт.

## 12. Перевод

- Строки к отправке режутся на пачки по BATCH.
- Адрес: у бесплатного ключа DeepL суффикс «:fx» — он ходит на
  `https://api-free.deepl.com/v2/translate`, платный — на
  `https://api.deepl.com/v2/translate`.
- Запрос POST, JSON: `{"text": [...], "target_lang": "RU",
  "split_sentences": "0"}`. Заголовок авторизации — `Authorization:
  DeepL-Auth-Key <ключ>` (не Bearer). `split_sentences=0` — не делить на
  предложения: надпись нужна цельной, а не литературным текстом.
- Ответ: списку `translations` сопоставляются строки пачки по индексу; пустой
  перевод не присваивается. Расхождение длин списков молча обрезается по
  короткому (так и в оригинале).
- HTTP-ошибка: счётчик ошибок сети +1, текст ошибки —
  `DeepL <код>: <первые 120 символов тела>`. Сетевой сбой —
  `сеть: <тип исключения>: <сообщение>`. Ошибки не роняют конвейер.

## 13. Сборка элементов отрисовки

Из учтённых в кадре строк с готовым переводом собирается список элементов
в порядке обхода; строка пропускается, если её рамка пересекается (IoU ≥
SAME_PLACE) с рамкой уже добавленного элемента — рисуем одну большую заливку,
а не несколько друг на друге.

Элемент несёт: рамку (fixed), текст перевода, стартовый размер шрифта
(высота рамки, делённая на число строк оригинала, `'\n' + 1`) и цвет фона.

Цвет фона: точки идут полосой шириной SAMPLE_BAND_PX **снаружи** рамки
(начиная с отступа 1 — на самой границе уже буквы), вышедшие за кадр
отбрасываются; цвет точки берётся `bitmap.getPixel`; по каждому каналу
берётся **медиана**, не среднее — один яркий пиксель (блик, курсор) не должен
уводить цвет. Если точек нет вовсе, цвет — чёрный (0). Цвет кодируется целым
ARGB с полной непрозрачностью.

## 14. Отрисовка

Оверлей перерисовывает Bitmap целиком при изменении списка:

1. Очистить Bitmap прозрачным.
2. Рамка каждого элемента заливается цветом его фона.
3. Цвет букв: яркость цвета фона (линейная sRGB: канал v (0..1) → v/12.92 при
   v ≤ 0.03928, иначе ((v+0.055)/1.055)^2.4; L = 0.2126R + 0.7152G + 0.0722B)
   ниже 0.45 — белый, иначе чёрный.
4. Размер шрифта подбирается бинарным поиском (FIT_STEPS делений пополам)
   в диапазоне [MIN_TEXT_PX, стартовый размер]: берётся наибольший размер,
   при котором высота перенесённого по словам текста шириной в рамку не выше
   высоты рамки × MAX_HEIGHT_GROWTH. Если максимум уже влезает — максимум;
   если не влезает даже минимум — минимум (низ обрежется, но показать почти
   всё лучше, чем не показать ничего). Шрифт полужирный, перенос по словам,
   выравнивание по центру, служебные вертикальные отступы выключены,
   интерлиньяж 0.92.
5. Текст рисуется по горизонтали по центру рамки, по вертикали — по центру
   (смещение = (высота рамки − высота текста) / 2, затем translate).

Оверлей перерисовывается только когда список элементов **действительно
изменился** (сравнение по значению с предыдущим показанным). Одинаковые
списки не рисуются — иначе перевод мигал бы на статичной картинке.

## 15. Статусная строка

Состояние для экрана обновляется после каждого кадра:

- «перевод ещё не запускался» — до старта;
- «захват экрана не создаётся» — захват не удался;
- «ошибка кадра: ...» / «кадр в Bitmap не получился» /
  «распознавание не удалось: ...» — точка сбоя в конвейере;
- «кадров: N, картинка пока не приходит» — ImageReader не отдаёт ничего;
- после успешного кадра:

```
блоков всего {N} (мусор {M}, русских {R})
строк в работе: {F}, показано: {P}
ошибок сети: {E}
```

где N — число блоков распознавания, F — число учтённых строк кадра, P —
число отрисованных элементов, E — счётчик ошибок сети; при наличии последней
ошибки сети она добавляется следующей строкой.

## 16. Экран приложения

- Сверху вниз: «Перевод: DeepL» (подпись обязательна по условиям
  бесплатного API), статус (переносить строки), кнопка.
- Кнопка запускает/останавливает службу; текст меняется по `isRunning`.
- Пока идёт перевод, статус обновляется раз в секунду; при возврате на экран
  (из настроек разрешений) рисуется актуальное состояние.
- Автоматическое копирование: логи с телефона не достать, а вставить текст в
  чат руками — лишняя ошибка. Копируется накопленный отчёт (статус + ошибка
  запуска + причина падения) один раз на изменение, не на каждом обновлении.
- Причина падения процесса (`ApplicationExitInfo`, Android 30+): обычный
  краш, нативный краш, ANR, сигнал, нехватка памяти, пользователь; со
  стек-трейсом до 4000 символов. Нужно потому, что нативное падение проходит
  мимо любого `try`.
- Ошибка запуска берётся из SharedPreferences (см. раздел 5).

## 17. Чистые функции (без Android, покрываются тестами)

- `normalize(text) -> str` — ключ строки (раздел 10).
- `looks_like_text(text) -> bool` — раздел 9.
- `is_russian(text) -> bool` — эвристика кириллицы ≥ 70 % при ≥ 3 буквах.
- `edit_distance_within(a, b, limit) -> bool` — полосное расстояние
  Левенштейна с ранним выходом, когда даже лучший элемент строки уехал за
  лимит.
- `box_overlap(a, b) -> float` — IoU рамок-кортежей; 0.0 при нулевом
  пересечении или нулевой площади.
- `same_place(a, b) -> bool` — IoU ≥ SAME_PLACE.
- `ring_points(left, top, right, bottom, band) -> [(x, y), ...]` — полоса
  точек снаружи рамки, отступ 1, без сортировки, повторы допустимы.
- `median_color(pixels) -> int` — медиана по каждому каналу ARGB-целых;
  пустой вход → 0.
- `luminance(argb) -> float` — относительная яркость (раздел 14).
- `fit_size(min_size, max_size, max_height, height_of) -> float` — раздел 14;
  height_of обязан расти с размером.
- `deepl_translate(key, chunks) -> (список | None, ошибка)` — раздел 12.
- `Pipeline` — конвейер кадра: фильтры, идентификация, стабилизация,
  перевод, сборка элементов, сравнение с показанным (разделы 9–14).
  Захват, распознавание и цвет подставляются снаружи: кадр — список
  `(рамка, текст, язык | None)`, цвет — функция от рамки.

## 18. Соответствие платформ (оригинал → порт)

| Kotlin-оригинал | Порт |
|---|---|
| Activity/Service на Kotlin | статические прокси Chaquopy, классы объявлены в манифесте |
| OverlayView (собственный View, setItems) | ImageView + рисование в Bitmap на рабочем потоке |
| toBitmap: поштучная сборка пикселей | построчная копия байтов + copyPixelsFromBuffer |
| BuildConfig.DEEPL_KEY / DEEPL_FREE | keys.py из секрета CI; адрес по суффиксу «:fx» |
| Geom.kt + GeomTest.kt | core.py + test_core.py (гоняются без телефона) |
| Executors.newSingleThreadExecutor | threading.Thread |
| companion object @Volatile | переменные уровня модуля |

## 19. Что совпадает с оригиналом намеренно

Порядок startForeground → захват; пересоздание захвата при повороте;
фиксация рамки при первом появлении строки; «ровно STABLE_SCANS»; восемь
параметров createVirtualDisplay; чтение resultData по версии Android
(getParcelableExtra с классом на 33+); иконка уведомления из системного
набора (android.R.drawable.ic_menu_search).

## 20. Сборка и проверка

- Тесты: `python3 test_core.py` — на любой машине, без Android (в сборке
  Chaquopy нужен buildPython той же версии, что и Python приложения).
- Сборка APK: GitHub Actions workflow `python.yml` — gradlew, Chaquopy 17.2,
  AGP 8.13, SDK 36, ABI arm64-v8a; ключ DeepL из секрета `DEEPL_API_KEY`
  записывается в keys.py перед сборкой; артефакт — `app-debug.apk`.
- Всё, что не покрыто тестами (захват, распознавание, сеть, отрисовка),
  проверяется только на реальном устройстве.
